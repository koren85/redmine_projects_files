# Каталог файлов проектов для Redmine 4.1

Таблица вложений одного проекта или всех доступных проектов: файл, проект,
задача/источник, автор, размер, дата. Скачивание по одному, ZIP выбранных файлов
или всех результатов фильтра (включая следующие страницы).

Фильтры: проект, номер задачи, автор, текущая группа автора и текущая роль автора
именно в проекте файла. Это не исторические группы/роли на момент загрузки.
Наследуемые через группы роли учитываются стандартными членствами Redmine.

Поддерживаются штатные вложения задач, проектов, версий, документов, Wiki,
новостей и сообщений форума. Незавершённые загрузки без источника и вложения
нестандартных сущностей сторонних плагинов не включаются. Репозитории Git/SVN
не являются вложениями и в каталог не входят. Архивные проекты не включаются.

## Установка в существующий Redmine

Проверено: официальный образ `redmine:4.1.7`, Ruby 2.6.10, Rails 5.2.6.3,
PostgreSQL 13.23. Требуется Ruby >= 2.4 (rubyzip 2.3.2).

1. Из корня Redmine установите плагин через Git:

   ```sh
   git clone https://github.com/koren85/redmine_projects_files.git plugins/redmine_project_files
   ```

   Либо распакуйте папку `redmine_project_files` в `REDMINE_ROOT/plugins/`.
   Название папки должно совпадать с указанным. Проверьте, что пользователь
   процесса Redmine может читать файлы и проходить по каталогам.
2. В корне Redmine выполните `bundle install` с обычными параметрами вашего
   приложения. Добавляется только зависимость `rubyzip ~> 2.3.2`.
3. Перезапустите Redmine. Миграции плагину не требуются.
4. В настройках нужных проектов включите модуль **Каталог файлов**.
5. В **Администрирование → Роли и права доступа** настройте права роли:
   - **Просмотр каталога и скачивание доступных вложений** — страница и скачивание
     только файлов, видимых этому пользователю через штатные права Redmine.
   - **Скачивание ВСЕХ вложений проекта (включая закрытые задачи)** — дополнительное
     право, открывающее все штатные вложения внутри разрешённого проекта.
     Для полного доступа нужны оба права. Вместе с файлом видны его название,
     описание, автор и название источника, включая тему закрытой задачи.
6. Назначьте эту роль выбранным участникам или группе в нужных проектах.

Общий каталог: `/project_files`. Каталог проекта:
`/projects/PROJECT_IDENTIFIER/project_files`. Ссылки появляются в меню Redmine.
Публичность проекта сама по себе не даёт доступ к плагину: требуется вход
и членство с соответствующей ролью. Администратор использует штатные привилегии
Redmine; модуль проекта должен быть включён.

В Docker папку плагина нужно сохранить в образе или подключить постоянным
bind mount. `docker cp` без изменения образа/тома потеряется при пересоздании
контейнера. Пример дополнительного Dockerfile для вашего базового образа:

```dockerfile
FROM redmine:4.1.7
COPY --chown=redmine:redmine redmine_project_files /usr/src/redmine/plugins/redmine_project_files
RUN bundle install --without development test
```

Используйте базовый образ и параметры сборки вашей существующей установки;
не заменяйте ими работающий compose-файл. Стенд ниже предназначен для отдельной
проверки, не для подключения к существующей БД.

## ZIP и ограничения

- Максимум 500 файлов и 512 МиБ исходных данных на один архив.
- Флажок в заголовке выбирает текущую страницу (50 строк).
- «Все по фильтру» скачивает результаты со всех страниц.
- Выбор флажками не сохраняется при переходе между страницами.
- Права повторно проверяются при скачивании каждого файла. Недоступный,
  несуществующий или отсутствующий на диске файл отменяет весь запрос.
- В ZIP имена имеют вид `ID_проекта/ID_вложения_имя`, поэтому одинаковые имена
  не перезаписываются. Имена кодируются в UTF-8; разделители путей заменяются.
- ZIP создаётся во временном файле и удаляется после передачи/закрытия ответа.
  Содержимое файлов читается блоками; весь ZIP в RAM не загружается.
- Для точной штатной проверки видимости каталог перебирает подходящие вложения
  пачками по 250 и хранит их ID. При десятках/сотнях тысяч вложений необходимо
  отдельно замерить время ответа и нагрузку на вашей базе.

## Отдельный Docker-стенд

Из папки плагина:

```sh
docker compose -p project-files-check -f integration/compose.yml up -d --build
docker compose -p project-files-check -f integration/compose.yml exec -e RAILS_ENV=production -e REDMINE_LANG=ru redmine bundle exec rake redmine:load_default_data
```

После запуска и завершения штатных миграций Redmine:
`http://127.0.0.1:3041`. Начальная учётная запись Redmine: `admin` / `admin`.
Только в отдельном стенде можно создать демонстрационный проект и пользователя:

```sh
docker compose -p project-files-check -f integration/compose.yml exec -e RAILS_ENV=production redmine bundle exec rails runner plugins/redmine_project_files/integration/demo.rb
```

Демонстрационный вход: `files_demo` / `Demo-files-41!`.

Проверки запускайте **только на отдельной тестовой БД**, с загруженными
стандартными справочниками Redmine:

```sh
docker compose -p project-files-check -f integration/compose.yml exec -e RAILS_ENV=production redmine bundle exec rails runner plugins/redmine_project_files/test/integration.rb
```

Тесты создают данные в транзакциях и откатывают их; отправка почты отключена.
Они не являются полной проверкой всех сценариев Redmine или совместимости
с вашими сторонними плагинами. Код плагина не патчит ядро, не меняет схему БД
и не изменяет/удаляет исходные вложения.

## Удаление

Отключите модуль в проектах, уберите папку плагина из образа/тома, выполните
`bundle install` и перезапустите Redmine. Откат миграций не нужен. Файлы
и записи вложений останутся в Redmine.
